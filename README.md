# Market Selector Combinator

适用于 Factorio 2.1 的脚本型选择运算器。

## 使用

1. 研究“电路网络”，制造并放置“市场选择运算器”。
2. 在输入端连接所需的红线或绿线；不同模式对输入信号的定义见下文。
3. 点击运算器，选择“生产订单”“超市订单”“配方查询”或“查询模式”，再填写当前模式的参数。
4. 从输出端读取结果；红线和绿线均可使用。

默认每 30 tick 更新一次，刷新间隔可在启动设置中调整。订单和配方模式只处理正数物品、流体或配方需求；配方信号按其主产物计算，并明确指定该配方，避免同一产品存在多个配方时选到另一条路径。查询模式只读取输入信号种类，不使用输入数量。生产订单同一时刻只会选择一个产品：产品库存低于基础订单量，并且每种配方原料库存严格大于 `单份用量 × 材料需求倍率` 时，启动并锁定该请求；锁定后直到产品库存达到 `订单量 × (1 + 额外可生产倍率)`，或任一种原料库存严格小于 `单份用量 × 原料保留倍率` 时，才释放并选择下一个产品。产品输出数量实时使用 `订单量 × (1 + 额外可生产倍率) - 当前库存`，原料输出数量按实际产品缺口向上取整到完整配方批次；材料需求倍率只用于启动校验。两组不同的启动、停止阈值共同提供迟滞空间。生产订单和超市订单都可配置与“切换订单”相同的红绿线路条件；超时时间大于 0 且条件满足时，会持续刷新计时起点。两种模式的“监控物品数量变化”默认为“是”，当前输出数量变化会重置超时；设为“否”后仅忽略这一种自动重置，线路条件仍然生效。条件中启用绿色线路的信号作为控制输入，不再同时作为订单处理。

配方选择仅考虑当前势力已由科技解锁且所选机器可制造的配方；优先使用主产品匹配或与物品同名的配方。

“超市订单”的库存校验现在有三档。“库存校验”使用红线库存，并按配方逐层展开；订单产品或缺口原料没有当前机器已解锁配方时暂时跳过。“库存校验（自动匹配关联箱）”仅在启用“关联箱和关联管”时出现，只把当前订单树涉及的产品、原料和校验副产品交给共享库存探针，不执行全量查询；有效库存为 `共享区库存 + 红线信号`，允许负红线抵扣并把最终结果限制为不小于 0。新订单会等待首份查询结果后再输出；已输出订单在查询空窗内保持信号并暂停计时，连续三份独立快照都确认缺料后才进入“原料等待时间”。“不校验”为默认值，所有原料都视为满足，直接输出订单产品或指定配方，但仍读取产品库存判断订单完成，并在单项顺序制作中按超时切到下一订单。

两种库存校验模式会为每台生产机器建立共享的产品能力和材料层级索引，并为每个运算器缓存各递归深度的结果。只要所选机器存在可用配方且尚未达到递归深度上限，就继续展开完整配方需求。“单个”模式按递归层级降序选择最底层缺口；最终产品以及每层可制造中间产品都有独立的基础目标和扩展目标。每种直接原料必须严格大于 `单份用量 × 原料需求倍率` 才启动，运行后严格低于 `单份用量 × 原料保留倍率` 才退回下层补料。“原料等待时间”只用于单个输出：确认需要撤销或切换后，先保持上一输出至等待期结束。“所有”模式同时输出展开范围内各层可制造缺口。递归深度为 0 表示不限制层数。绿色订单信号仍按当前输出、等待、异常和库存充足排序；悬浮说明会突出当前制作、缺口及未输出原因。

每个可制造递归中间产物先使用整单的额外生产目标；仅当 `父配方单份用量 × 材料需求倍率` 大于该目标时，才改用 `父配方单份用量 × (1 + 材料需求倍率)`，避免小订单达到普通目标后仍跨不过材料启动线，同时不会让材料需求倍率重复乘订单总量。此规则用于两种库存校验模式：“单个”保持到库存严格大于该目标，“所有”输出到该目标的精确缺口；最终订单仍只使用额外生产倍率。

库存校验中的不可制造终端原料只作为生产门槛：库存必须严格大于 `单份用量 × 材料需求倍率`；满足后放行最近的可制造上层物品，但该终端原料本身不会作为生产信号输出。切换库存校验来源会立即清除旧线路输出并重新计算；自动关联库存的结果新鲜度仍受“关联箱和关联管”自身同步频率影响。

“配方查询”不区分红绿输入，将输入物品、流体或配方视为待查询产品，并输出所选机器能够制造该产品所需的直接原料；输入配方时直接使用该配方，查询不受科技解锁状态限制。“多配方支持”为“单个”时，只查询稳定排序后的第一个正数输入并按一份配方输出；选择“所有”后，会合并全部正数输入，按产品数量向上取整到完整制造次数并汇总原料。此时缓存格子数为 0 会保持完整输出；非 0 时按各配方需求比例、完整制造批次和物品堆叠上限缩放到可容纳的原料量。找不到配方的输入不会产生输出。

“查询模式”依赖可选模组 `LinkedChestAndPipe >= 1.2.96`。未启用该模组时，本模式忽略所有输入且不输出信号。“查询模式”参数可限制为“仅流体”“仅物体”或默认的“不限制”，此限制同时作用于按输入查询和“查询全部”。默认“查询全部”为“否”，红绿输入中的物品、流体信号用于指定查询种类，配方信号会先转换为该配方的主产物；输入数量不参与计算。设为“是”后忽略输入，输出当前势力共享区内符合类型限制的全部非零库存。读取通过每个势力永久复用的隐藏 `share-network-output` 探针完成，因此新查询条件最多需要等待对方模组约 120 tick 的刷新周期。

“切换订单”合并红绿输入，并按输出模式保留液体、物品或虚拟信号。timeout 为 0 时直接输出初始顺序；大于 0 时，条件持续成立至指定秒数便推进到下一种信号全排列。输入信号种类变化或点击“清空切换”后，从初始顺序重新开始；仅数量变化会保持当前排列和计时。

## 代码结构

- `control.lua`：运行阶段入口，处理实体生命周期、电路信号、模式调度、输出代理和事件分发。
- `scripts/modes/`：各操作模式彼此独立的计算模块。
- `scripts/gui.lua`：独立 GUI 模块，只负责窗口创建、参数区域显隐、连接状态刷新和关闭行为；不直接读取 `storage`，也不参与生产计算。

代码中的 `---@param` 和 `---@return` 是 Lua Language Server 可识别的类型注释；普通中文注释会进一步解释对应 Factorio API 的用途和采用该设计的原因。

选择运算器本体的图标层会展示当前锁定的待生产产品；当前没有待生产产品时显示问号。图标使用独立渲染层，不会写入线路。

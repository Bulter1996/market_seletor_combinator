# Market Selector Combinator

适用于 Factorio 2.1 的脚本型选择运算器。

## 递归配方策略与生产网络

在超市订单绿色输入上 **Shift+左键**，打开可折叠递归树。点击材料节点配置多个候选配方，
每个候选分别设置优先级、原料需求倍率和原料保留倍率。策略在本组合器内按材料与品质共享；
自动选择和手动策略的实际配方均高亮，所有可制造节点输出配方信号，库存仍按实际产物计算。
全部直接原料严格超过需求阈值才能启动；任一原料小于等于保留阈值时不可继续。
已经执行的候选不会仅因更高优先级候选恢复而切换。旧版根配方和多产物库存条件保留。

超市参数区新增四个默认关闭的开关：发布缺料、承接网络任务、允许请求跨星球、接受跨星球请求。
同阵营共用一个网络，跨星球分配要求双方许可；发布请求需要启用库存校验。
每个任务唯一分配，按生产者优先级、任务数和实体编号选取；承接方继续使用自己的配方、
额外生产和原料参数。多个制造环节可继续发布子任务，循环依赖与超过 16 层的请求会显示阻塞。

本地订单与网络任务在**当前生产物品节点**完成或不可继续时重新竞争，同优先级本地优先。
整个网络父任务不会锁住组合器；本地恢复也不会打断正在执行的网络物品节点。
本地库存目标受保护，同一红线电路网络共享承诺账本，物品不能重复交付。
独立电路如果读取同一个物理仓库，需由一个承接方代表该库存接单。

承接方红线库存达到生产目标后，任务变为“待运输”，不会因为库存下降而再次派单。
运输由工厂自身处理；请求方库存缺口消失或源订单取消后释放承诺。
快捷栏的“生产网络”入口显示任务数、物品请求量、来源/承接组合器与星球、配方和状态，
支持折叠子任务、定位组合器、以及“释放承诺并重新请求”。仅在原供货承诺丢失时使用后者，
否则仍在运输途中的货物可能被重复生产。

## 使用

1. 研究“电路网络”，制造并放置“市场选择运算器”。
2. 在输入端连接所需的红线或绿线；不同模式对输入信号的定义见下文。
3. 点击运算器，选择“超市订单”“配方查询”“查询模式”或“切换订单”，再填写当前模式的参数；超市订单递归深度设为 0 时直接输出订单物品。
4. 从输出端读取结果；红线和绿线均可使用。

默认每 120 tick 更新一次，刷新间隔可在启动设置中调整。订单和配方模式只处理正数物品、流体或配方需求；配方信号按其主产物计算，并明确指定该配方，避免同一产品存在多个配方时选到另一条路径。查询模式只读取输入信号种类，不使用输入数量。旧版“生产订单”仅为已有存档保留运行兼容，不再出现在模式入口，也不作为超市订单后续功能的依赖；新配置使用递归深度 0 的超市订单直接生产订单物品。

配方选择仅考虑当前势力已由科技解锁且所选机器可制造的配方；优先使用主产品匹配或与物品同名的配方。

“超市订单”的库存校验有三档。“库存校验”使用红线库存并按配方逐层展开；根订单本身没有当前机器已解锁配方时才跳过，原料不足不会终止订单，而会继续输出对应层级的生产缺口。“库存校验（自动匹配关联箱）”仅在启用“关联箱和关联管”时出现，只查询当前订单树涉及的信号；有效库存为 `共享区库存 + 红线信号`，允许负红线抵扣并把结果限制为不小于 0。“不校验”为默认值，所有原料都视为满足，直接输出订单产品或指定配方，但仍读取产品库存判断订单完成。

两种库存校验模式会为每台生产机器建立共享的产品能力和材料层级索引，并为每个运算器缓存各递归深度的结果。“单个”模式下，勾选“顺序制作”时先完成当前订单的原料链和订单物品，再处理下一订单；不勾选时汇总全部订单，从最深原料层逐层处理到订单物品。原料不足不会让队列扫描后停止。生产倍率直接表示需求数量的倍数，左侧固定为 1，右侧必须大于 1、默认 2。每种直接原料必须严格大于 `单份用量 × 原料需求倍率` 才启动，运行后严格低于 `单份用量 × 原料保留倍率` 才退回下层补料。“原料等待时间”只用于单个输出。“所有”模式同时输出展开范围内各层缺口。递归深度为 0 表示不递归，只生产当前所需的订单物品。

每个可制造递归中间产物先使用整单的生产倍率目标；仅当 `父配方单份用量 × 材料需求倍率` 大于该目标时，才改用 `父配方单份用量 × (1 + 材料需求倍率)`，避免小订单达到普通目标后仍跨不过材料启动线，同时不会让材料需求倍率重复乘订单总量。“单个”保持到库存严格大于该目标，“所有”输出到该目标的精确缺口；最终订单直接使用 `订单需求 × 生产倍率`。

库存校验中的不可制造终端原料只作为生产门槛：库存必须严格大于 `单份用量 × 材料需求倍率`；满足后放行最近的可制造上层物品，但该终端原料本身不会作为生产信号输出。切换库存校验来源会立即清除旧线路输出并重新计算；自动关联库存的结果新鲜度仍受“关联箱和关联管”自身同步频率影响。

“配方查询”不区分红绿输入，将输入物品、流体或配方视为待查询产品，并输出所选机器能够制造该产品所需的直接原料；输入配方时直接使用该配方，查询不受科技解锁状态限制。“多配方支持”为“单个”时，只查询稳定排序后的第一个正数输入并按一份配方输出；选择“所有”后，会合并全部正数输入，按产品数量向上取整到完整制造次数并汇总原料。此时缓存格子数为 0 会保持完整输出；非 0 时按各配方需求比例、完整制造批次和物品堆叠上限缩放到可容纳的原料量。找不到配方的输入不会产生输出。

“查询模式”依赖可选模组 `LinkedChestAndPipe >= 1.2.96`。未启用该模组时，本模式忽略所有输入且不输出信号。“查询模式”参数可限制为“仅流体”“仅物体”或默认的“不限制”，此限制同时作用于按输入查询和“查询全部”。默认“查询全部”为“否”，红绿输入中的物品、流体信号用于指定查询种类，配方信号会先转换为该配方的主产物；输入数量不参与计算。设为“是”后忽略输入，输出当前势力共享区内符合类型限制的全部非零库存。读取通过每个势力永久复用的隐藏 `share-network-output` 探针完成，因此新查询条件最多需要等待对方模组约 120 tick 的刷新周期。

“切换订单”合并红绿输入，并按输出模式保留液体、物品或虚拟信号。候选首次按数量降序排列、同量按信号 ID 排序，并只锁定前两项：第一项在红线输出排名 101，第二项在绿线输出排名 102；只有一个候选时，两条线路都输出该信号的排名 101。第三项以后不会输出，可在输入信号槽悬浮查看原因。仅数量变化会保持锁定结果和计时；信号种类变化或点击“重新选择”才重新选取。timeout 为 0 时不交换；大于 0 时，所有超时时间重置条件持续不满足达到指定秒数后交换红绿输出。关闭循环时只交换一次，启用后每次超时继续往返交换。

## 代码结构

- `control.lua`：运行阶段入口，处理实体生命周期、电路信号、模式调度、输出代理和事件分发。
- `scripts/modes/`：各操作模式彼此独立的计算模块。
- `scripts/gui.lua`：独立 GUI 模块，只负责窗口创建、参数区域显隐、连接状态刷新和关闭行为；不直接读取 `storage`，也不参与生产计算。

代码中的 `---@param` 和 `---@return` 是 Lua Language Server 可识别的类型注释；普通中文注释会进一步解释对应 Factorio API 的用途和采用该设计的原因。

选择运算器本体的图标层会展示当前锁定的待生产产品；当前没有待生产产品时显示问号。图标使用独立渲染层，不会写入线路。
